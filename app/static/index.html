How it works

  • Request flow: the requested model's own providers first; if all fail (or the model doesn't exist), the explicit chain, then auto-picked healthy stand-ins.
  • Auto-pick ranks healthy models by matching capabilities (tools always, reasoning/vision preferred) and lowest latency.
  • Media routing: when a request carries images / audio / video / PDFs the selected model can't read, a capable stand-in serves it first — same spoofed id, no agent errors. Plain-text files are inlined so every model can read them. Opt-out env: NOVA_MEDIA_ROUTING=0.
  • The response model field (and every SSE chunk) always shows the requested id — _nova.upstream_model and the Logs tab reveal what really served it.
  • Env switches: NOVA_AUTO_FALLBACK, NOVA_SPOOF_MODEL, NOVA_FALLBACK_MAX, NOVA_MEDIA_ROUTING. Per-request opt-out: {"nova":{"spoof_model":false}}.

How auto-activation works

  • Every enabled extension tool is auto-injected into POST /v1/chat/completions — any client with a gateway key gets it, zero code changes on their side.
  • When the model calls a Nova-injected tool, NovaRouter executes it (MCP call / skill return / plugin HTTP) and feeds the result back to the model — up to 5 rounds — then returns the final answer.
  • Client-declared tools are passed through untouched. Opt out per-request with {"nova":{"auto_tools":false}}.
  • Discover tools: GET /v1/tools · call directly: POST /v1/tools/<name>

Point any agent at NovaRouter

Use the gateway base URL below with any OpenAI-compatible SDK or tool, and one of your generated gateway keys.

OPENAI_BASE_URL = http://127.0.0.1:8080/v1
OPENAI_API_KEY  = nova-...            # created in "Access Keys"

curl $OPENAI_BASE_URL/chat/completions \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"groq/llama-3.3-70b-versatile","messages":[{"role":"user","content":"hi"}]}'

# python
from openai import OpenAI
c = OpenAI(base_url="http://127.0.0.1:8080/v1", api_key="nova-...")
print(c.chat.completions.create(model="groq/llama-3.3-70b-versatile",
      messages=[{"role":"user","content":"hi"}]).choices[0].message.content)

GET /v1/models lists every enabled model with its provider and last known health. Streaming ("stream":true) is supported, including Anthropic-native providers which are translated to OpenAI SSE chunks.

How routing works

  • Requested model id is matched against exposed_id, then raw upstream id, then providername/model.
  • If several providers serve the same id, the healthiest/fastest one goes first, the rest are failover.
  • Within a provider, keys rotate round-robin by weight; a key hitting 429/402/401/5xx gets a cooldown and is skipped.
  • Non-retryable upstream errors (like a malformed request) are returned immediately instead of burning other keys — unless a fallback route remains, since the model itself may be the problem.
  • Model fallback (Fallbacks tab): when every provider for the requested model fails — or the model isn't registered at all — the configured chain, then auto-picked healthy stand-ins, serve the request instead. The response (and every stream chunk) still reports the model id the client asked for; the Logs tab and _nova metadata record what actually answered.
